# #241 verification: no recaps in Claude and Codex tabs

Revision `0206db9` (change), verified on olw-win10 (WSL Ubuntu + Windows 11), Claude Code 2.1.332, codex-cli 0.172.0.

- Source of the switches: Claude Code reads `CLAUDE_CODE_ENABLE_AWAY_SUMMARY` before the user's `awaySummaryEnabled` setting (a falsy value turns away summaries off). Codex has a boolean `tui.auto_recap` ("Automatic recaps"); `codex -c 'tui.auto_recap="x"' features list` fails with `invalid type: string "x", expected a boolean in tui.auto_recap`, `-c tui.auto_recap=false` is accepted. `codex exec` and `codex resume` both take `-c`.
- `dotnet build src/BoosterAI -c Release`: 0 warnings, 0 errors. `dotnet test tests/BoosterAI.Tests` (WSL): 1541 passed, 0 failed. New `RecapTests` cover every catalog Claude model plus a custom ID on start, tracked start, continue, restart (fresh and continued), Run once, save-and-close and the auto-compact guard; Codex start, continue, restart and `exec`; no opt-out for agy, aider, OpenHands and Open Interpreter; and a real bash run through a `claude` alias showing the CLI sees `0` while the shell stays unset. Existing exact-command tests were updated for the new prefix/flag.
- `BoosterAI --dry-run` with a neutral config: `CLAUDE_CODE_ENABLE_AWAY_SUMMARY=0` before every claude command (start, `--continue`, restart) and `-c tui.auto_recap=false` in codex start, `resume --last` and restart.
- Windows Terminal: [CommandCheck](CommandCheck/Program.cs) (adapted from #174) ran the generated `Launcher.TabScript` in one named portable Windows Terminal 1.24.12741.0 window on a private desktop with a neutral settings file; a fake `claude` function recorded the variable. Result: [windows-command.json](windows-command.json) (`markerValue` `0`, foreground unchanged, terminal closed).
- Not verified: a live recap being absent after real idle time with a real account (that needs minutes of idle time and spends tokens); the switch is the CLI's own documented control.
